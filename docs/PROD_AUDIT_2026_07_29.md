## P0 — confirmed blockers

### [Atrium] Relay tile content is hardcoded English — no i18n across nl/de/es/fr
- **surface:** atrium-relay-board
- **file:** `src/components/ui/HomeView.tsx`
- **detail:** AtriumRelay is fed by HomeView, where nearly every user-facing tile string is a raw English literal instead of t(): anchor titles/descs ('Enter Your Palace'/'Walk through your rooms in 3D', 'Enter Your Library'/'Your whole collection'), all lane tiles ('Add Photos', 'Import from Cloud', 'Restore a Photo', 'Write a Memory', 'Interviews', 'Capture by WhatsApp', 'Time Capsule', 'Memory Map', 'Timeline', 'Highlights', 'Family Tree', 'Create a Gallery', 'Tidy Your Rooms', 'Explore', 'Life Story', 'Start a Family Group', 'Build Together', 'Invite Relatives', 'Share Publicly'), the YOU pills ('Milestones','Your Profile','Settings','Help & Guides'), and several suggestion cards ('Your family shared with you','On this day','Bring in your first photos','Record your story'). Only a subset (relay.eveningFind, relay.sixtySeconds, relay.familyEmbers, board labels) uses t(). A Dutch/German/Spanish/French user sees a fully English relay board.
- **fix:** Route every title/desc/label/reason and the interview 'recorded'/'steps' datum suffixes through t() with relay.* keys added to all five messages files (en/nl/de/es/fr). This is the single biggest multimodality gap on the surface.

### [Library] iPad portrait renders the tiny-touch desktop sidebar (isMobile prop is not iPad-aware)
- **surface:** library-sidebar
- **file:** `src/components/ui/LibrarySidebar.tsx`
- **detail:** The component branches solely on the injected isMobile boolean (if isMobile return mobile pill strip, else desktop). isMobile derives from useIsMobile whose query is (max-width: 767px), (max-height: 500px). iPad portrait is 768-1024px wide, so isMobile is FALSE and the full 17rem desktop sidebar renders on a touch-only tablet. That desktop tree is built for a mouse: room rows are ~1.5rem tall, the info ? button is 0.875rem, the color dot hit box is 1.5rem, and color swatches are 1.125rem — every one far below the 2.75rem touch minimum. Hover-only affordances (chevron opacity, color-dot opacity 0.6->1 on hover) also never trigger on touch. This same code path also forces the sub-16px search input onto iPad, causing iOS zoom-on-focus.
- **fix:** Gate the layout on useIsCompact() (max-width:1024px) or useIsTablet() rather than the phone-only isMobile prop, so iPad portrait gets touch-sized targets. At minimum, bump room-row / tooltip / color-dot / swatch hit boxes to >=2.75rem when useTouchControls() is true.

### [Settings] Permission toggle silently no-ops on the server (field-name casing mismatch)
